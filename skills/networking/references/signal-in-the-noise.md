# Be the signal in the noise: the framing lens for every CV and outreach draft

Adapted from Ha Nguyen's guest post on Deb Liu's *Perspectives* newsletter (Sept 2026).

Apply this whenever you help with the user's job search: the CV tagline or summary line, bullets,
cover letters, LinkedIn DMs, cold emails, intro requests, referral blurbs.

The premise: hiring now works like a venture deal funnel. A hiring manager skims hundreds of
applicants, talks to a dozen, and hires one. So the job of every artifact is not to be complete.
It is to be the **signal** a skimming reader cannot miss.

## The four moves

### 1. Make the signal obvious: answer "Why me?" at the top

The resume or message should answer "why this person, out of a thousand applicants" immediately,
and make the answer hard to dispute.

- **CV tagline / summary line:** must answer *why the user for this role* in one line, not describe
  them in general. Test: cover the rest of the page. Does the tagline alone tell the reader which
  of their requirements the user already meets? If it could sit on the CV for any company, it is
  noise.
- **Top bullets:** the first bullet under each role proves the tagline's claim. Order bullets by the
  JD's top requirement, not chronology or pride.
- **Outreach:** the "why me" lands in the first two sentences, next to the ask.

### 2. Get vouched for: warm beats cold

A recommendation from someone the hiring manager trusts does in one sentence what several interview
rounds try to find out. It is a separate, privileged track.

Before drafting a cold application, check for a warm path: the tracker's Notes column,
`profile/contacts.md`, shared schools and past employers in `profile/me.md`. If there is one, the
best draft is often the **referral blurb** the user hands that person, not the cover letter. If
there is none, message the decision-maker directly; that also works.

### 3. Center it on what *they* are building, not the user's bio

A strong note says: here is what you are trying to build; here is why my specific experience helps
you get there.

Structure for DMs, emails, cover-letter openers: **their goal (from public facts) → the specific
experience of the user that moves it → the ask.** A generic bio summary is the failure mode.

Reconcile with the networking rule "never presume the recipient's situation": name what the
**company** is building from things it has said publicly (JD, launch post, product, blog). Never
assert the recipient's day-to-day, pain, or wheelhouse. "Your JD says you're taking the product
from pilot to production" is fine. "This must be keeping you up at night" is not.

### 4. Show, don't tell: lead with the artifact

A link to something the applicant built changes how the reader judges everything after it. A
working prototype, analysis, or writing sample shows how someone thinks under real constraints,
not what they claim on paper.

When the user has built something that maps to the role:
- put the link **in the first lines** of outreach, not the P.S.;
- in the CV, name the built thing with its link and one hard number, rather than "experience with X";
- if nothing maps and the role matters, suggest the `project` skill *before* writing the outreach.

Every artifact link must be live and verifiable. Check it before it goes in a draft.

## The final gate: run on every draft before showing the user

> "Is this the pitch I would say yes to?"

Read the draft as the hiring manager on application #400. Check:

1. **Why me in the first line?** Tagline or opening sentence names the match to *their* top need.
2. **Their world, not the user's bio?** At least one line about what they are building, from public
   facts.
3. **Proof, not claims?** A link, a number, or a named artifact, not an adjective.
4. **Warm path checked?** If a referral path exists, tell the user before they send cold.
5. **Hard to say no to?** If it could go to ten companies unchanged, it is spray-and-pray. Rewrite.

Report the result in one line with the draft (for example: *"Signal check: why-me in line 1,
prototype link up front, no warm path found"*). This check is about **framing**; facts still come
from `profile/evidence.md`, and wording still goes through `voice` and `aislop`.
